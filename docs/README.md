# OMP Learner Maintainer Documentation

This directory documents Learner's own behavior, implementation, and integration contracts for maintainers and reviewers. It is not a store for general knowledge collected from other projects. Maintained reusable learning belongs in the user's configured shared knowledge base, defaulting to [`marlens-skills-rules-and-tools`](https://github.com/klondikemarlen/marlens-skills-rules-and-tools); project-specific knowledge belongs with its owning project. The [ownership and signal model](architecture/ownership-and-signals.md) explains classification, configurable proposal routing, supplied-verifier handoff, and the evidence supporting those boundaries. Its [coverage outcomes and needless-helper example](architecture/ownership-and-signals.md#current-shared-guidance-coverage) explain when an ordinary already-tracked human correction completes Learner's role; [`omp-verifier` separately owns code-adherence evaluation and verification evidence](https://github.com/klondikemarlen/omp-verifier/blob/main/docs/references/verifier-concepts-reference.md#ownership-boundaries).

## Maintainer Entry Points

- [Notification text and structured evidence](architecture/ownership-and-signals.md#operation-results-and-silence): distinguish the readable ticket outcome from coverage and memory records retained for inspection.
- [Evidence and source conflicts](architecture/ownership-and-signals.md#evidence-and-source-conflicts): distinguish formatter guarantees, native delivery observations, and optional model-selected records.
- [Release and install verification](/README.md#release-and-install-verification): prove the released extension is installed and registered in a fresh OMP process, separately from local checks.

## Authority and Publication

- Current implementation behavior is defined by [`config.mjs`](/omp-plugin/learner/config.mjs), [`source.mjs`](/omp-plugin/learner/source.mjs), [`ticket.mjs`](/omp-plugin/learner/ticket.mjs), and [`report.mjs`](/omp-plugin/learner/report.mjs): advisor policy, authoritative native source inspection, proposal routing/acknowledgment, and notification text versus structured records.
- Focused evidence has separate owners: [`verify-learner.mjs`](/scripts/verify-learner.mjs) exercises configuration and ticket behavior; [`verify-learning-reports.mjs`](/scripts/verify-learning-reports.mjs) exercises readable ticket outcomes and preservation of supplied structured records; [`verify-eval-transport.mjs`](/scripts/verify-eval-transport.mjs) exercises generated JavaScript transport examples; [`verify-native-replay.mjs`](/scripts/verify-native-replay.mjs) and [`verify-native-workflows.mjs`](/scripts/verify-native-workflows.mjs) exercise selected live-advisor delivery and silence scenarios with isolated GitHub responses. Passing a check proves only its exercised cases, not universal semantic eligibility or a released installation.
- This repository is the publication boundary for these project docs. If a documentation site is added, explicitly allowlist public inputs rather than publishing this tree implicitly.
